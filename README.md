# Phantom Remote for macOS — Unofficial

🇩🇪 [Deutsche Version](README.de.md)

A small, **unofficial beta remote control** for Devialet Phantom speakers running DOS 2 with the IP Control API. Native macOS app with a window, a menu bar item and global keyboard shortcuts.

**Not developed, reviewed or supported by Devialet.** Devialet and Phantom are trademarks of their respective owners. This project contains no manufacturer photos or logos.

## Transparency: fully “vibe-coded”

This project was created entirely through **vibe coding with AI assistants**. The initiator had the idea, described what he wanted and gave feedback on usability and appearance. **He did not write any code himself.** Code, revisions, tests and documentation were generated by **Claude Code and OpenAI Codex**. The first version was written with Claude Code; Codex then reviewed it and reworked it for this public beta, and Claude Code continued from there.

There has been **no independent human code audit** so far. Automated tests and successful builds do not guarantee correctness. Contributions, independent reviews and reproducible bug reports are welcome. This is an experimental community tool with no official support and no claim of full device compatibility.

## Features

- mDNS/Bonjour discovery of `_devialet-http._tcp.local.`, including the advertised port.
- Alternatively enter an IPv4/IPv6 address or host name with an optional port.
- Explicit system selection. Device **and** system are stored by their IDs and re-verified before every write command. No automatic switch to another system after an outage.
- Volume, mute, supported playback commands and separate optical/analog inputs per speaker.
- Night mode, equalizer and balance, as far as the firmware offers these endpoints.
- Identify tone per speaker plus a check of its HTTP reachability (the milliseconds shown are HTTP response times, not ICMP ping).
- Freely resizable window without scrolling: text, dial, speakers, buttons and spacing scale with the window. Small shows only the volume dial, regular the full controls, large/full screen three columns with “Now Playing” and big previous/play/next buttons (if the source offers them).
- User interface in **English and German**; the app follows the system language (other languages → English).
- Menu bar control and global shortcuts: **⌃⌥↑**, **⌃⌥↓**, **⌃⌥M**.
- Visible error messages. Failed commands are never shown as successful.
- Update check on demand (footer or app menu “Check for Updates…”), optionally once a day. **“Install Update”** downloads, verifies and installs the new version inside the app and relaunches – only when you click, never silently (see “Self-update”).

## Requirements and tested scope

- **macOS 14 or later**. Universal build for **Apple Silicon and Intel**.
- To build: current Xcode Command Line Tools with **Swift 6** (or Xcode). No external Swift or Python packages.
- Mac and speakers must reach each other on the network. mDNS needs multicast; across VLANs you may have to enter the address manually.
- Phantom with DOS 2 and the HTTP IP Control endpoint, usually TCP port 80. DOS 1 / Spark is not supported.
- Development started with a **Phantom II 95 dB stereo pair on DOS 2.21.2**, where individual API functions were verified. The beta is additionally tested against a simulated transport. Other devices, firmware versions, Intel Macs and all macOS versions have **not** been fully tested in practice.

## Download (beta, not notarized)

[Releases](https://github.com/ioni17schick/phantom-remote-macos/releases) contain a ready-made universal app as `Phantom-Remote-<version>-unsigned.zip`.

**Important:** The app is only *ad hoc* signed and **not notarized by Apple** (no Developer ID), so macOS blocks it on first launch. It is built by GitHub Actions directly from the tagged source, not on a private machine; origin and integrity can be verified:

```sh
shasum -a 256 -c Phantom-Remote-*-unsigned.zip.sha256
gh attestation verify Phantom-Remote-*-unsigned.zip --repo ioni17schick/phantom-remote-macos
```

Opening it (macOS 15 and later):

1. Unzip, drag **Phantom Remote.app** to *Applications* and double-click it once. macOS reports that it cannot verify the app → **Done**.
2. **System Settings → Privacy & Security**, scroll to the bottom → next to “Phantom Remote” click **Open Anyway** → confirm with your password.
3. From then on the app opens normally.

This is a deliberate exception to macOS protections. Only do it if you trust the project; otherwise build the app yourself as described below – self-built apps are not affected.

## Self-update

“Install Update” downloads this repository’s release zip from GitHub, verifies it and replaces the running app:

1. Only downloads below `github.com/ioni17schick/phantom-remote-macos/releases/download/…`; redirects only to `*.githubusercontent.com`, HTTPS only.
2. The SHA-256 must match the `.sha256` file of the same release.
3. The archive must contain exactly one app with the identifier `org.phantomremote.mac`, the expected version and a valid code signature.
4. The previous version is moved to the **Trash** (recoverable); if the replacement fails, it is put back automatically.

**Deliberate trade-off:** A file downloaded by the app itself carries no quarantine flag, so macOS does not ask “Open Anyway” afterwards. The checks protect against broken downloads and foreign servers, **not** against a compromised GitHub account of this project. If you don’t want that, use the Safari button next to it (release page) or build the app yourself. If the app runs from a read-only location (e.g. straight from Downloads), it only offers the download.

## Build and run

```sh
./test.sh
python3 scripts/check_localization.py
./build.sh
open ".build/Phantom Remote.app"
```

`build.sh` only builds into `.build/`. It does not quit a running app or touch an installed version. To install after quitting the app via **Quit**:

```sh
./build.sh --install
```

This installs to `~/Applications/Phantom Remote.app`; an existing version is kept as `.bak-beta-<date-time>`. A running instance prevents the installation.

Local builds are **ad hoc signed and not notarized**. Smooth Gatekeeper handling for public downloads would require Developer ID signing and Apple notarization; the release downloads are therefore explicitly labelled *unsigned*.

## Signed release builds (maintainers)

`scripts/release.sh` builds, signs with *Developer ID* and hardened runtime, has the app notarized by Apple and staples the ticket. Result: `dist/Phantom-Remote-<version>.zip` plus a SHA-256 file. Required once:

1. A **Developer ID Application** certificate in the keychain (Apple Developer Program, *Account Holder* role).
2. Stored notarization credentials, e.g. with an app-specific password:
   `xcrun notarytool store-credentials phantom-notary --apple-id <Apple ID> --team-id <TEAMID>`

The script aborts without certificate or profile and publishes nothing by itself.

## First connection

1. Open the app and allow local network access if macOS asks.
2. Open **Devices… → Search Network (mDNS)**.
3. Select the **system leader** of the pair. The app stores the confirmed device/system identity and address locally.
4. Alternatively enter an IP address or host name and click **Check**. Examples: `192.0.2.10`, `phantom.local:80` or `[2001:db8::10]:80` (documentation addresses, not real devices).
5. For the second speaker’s test tone its address must be known too. mDNS finds both; without mDNS add both addresses individually. Adding the second speaker does not change the selected system.

Discovery never picks an arbitrary first device. If the address changes while device and system IDs stay the same, mDNS can update it. After a reset, regrouping or a leader change you may need to select the system again.

## Volume and controls

- Drag the dial up or down. It works **relatively**, so a click in the middle never causes a volume jump.
- Write commands are processed in order; fast key presses are not lost.
- **Default limit: 60 of 100**, adjustable under **Devices…**. It limits commands from this app, not the device. Other apps and sources can still turn it up; a higher volume is left unchanged, turning it down still works.
- This is not a guaranteed hearing-safe level. Start playback at a low volume.
- Turning the volume up does not unmute automatically.
- Clicking a speaker requests its identify tone. The display confirms the successful HTTP request, not an acoustic measurement.
- Closing the window keeps the app running for the menu bar and shortcuts; **Quit** ends it.

## Audio from the Mac

This app is a **remote control, not an audio driver**. To play sound from the Mac, select the speaker via AirPlay or a suitable cable connection. The AirPlay button opens the macOS sound settings; it does not connect by itself. Lip sync depends on the source, the player and the transport.

## Limitations of this beta

- Controls one selected system with up to two speakers. No multiroom editor, pairing or firmware updates.
- Identify uses `/devices/current/identify`, an endpoint confirmed in practice but **treated as undocumented** here. It may be missing on other firmware; an error message is shown then.
- Standby/power off has been removed from the beta because the command and wake-up behaviour were not sufficiently verified.
- Balance is offered conservatively from −10 to +10. EQ range and presets come from the device.
- The network API has no authentication and uses plain HTTP. Identity checks protect against accidental mix-ups, **not against active spoofing on the network**. Use only on trusted local networks; never forward the port to the internet.
- Failed write commands are not retried automatically. After an uncertain result, queued commands are dropped and the state is read again (a command that the source simply doesn’t support does not drop the queue).
- mDNS problems: check macOS local network permission, firewall, VPN, guest network and multicast; alternatively add both speakers by IP. IPv6 zone identifiers are not supported.
- Global shortcuts can collide with other apps; the app names the shortcuts it could not register.

## Privacy

No telemetry, no cloud account and no downloading of product images. The app talks to the devices it discovers or that you enter. The only exception is **update check and self-update**: they query the public GitHub API for this project’s releases – only when you click, or at most once a day at launch if you enable it under **Devices…** (off by default). Only `PhantomRemote/<version>` is sent as user agent; as with any request, GitHub sees your IP address. The selected system, device IDs, addresses, volume limit and update setting are stored in macOS UserDefaults (`org.phantomremote.mac`). No device IDs or private addresses are preset in the source code.

Please check bug reports and screenshots for private names, IDs and addresses before posting.

## Tests and project layout

```sh
./test.sh                               # regression tests (simulated speaker only)
python3 scripts/check_localization.py   # every visible text has an English translation
python3 scripts/package_source.py --check
```

The regression tests use only an injected mock transport, never real speakers. Among other things they cover address validation, device identity checks, the volume limit, fast command sequences, stale polling responses, error display, multiple optical inputs, per-device identify, the update checker and the self-update verification (with a real signed test app).

| File | Purpose |
|---|---|
| `Models.swift` | API data, address validation, HTTP transport, volume rules, layout scaling |
| `Discovery.swift` | Bonjour/mDNS discovery |
| `Updates.swift` | Version comparison, update check and verified self-update |
| `Core.swift` | State, fixed device binding, ordered commands |
| `Views.swift` | User interface and the original, neutral speaker graphic |
| `App.swift` | App window, menu bar, menus |
| `Resources/*.lproj` | Translations (keys are the German source texts; `en.lproj` = English) |
| `Tests/RegressionTests.swift` | Isolated regression tests |
| `build.sh`, `test.sh`, `scripts/` | Build, tests, localization and publication checks, releases |
